### T1 — one sample failed, and it is not a regression

The first T1 sample had **74 unclosed tags** and 6 mismatched end tags (`</span>` closing
while `<strong>`/`<div>` was innermost) → FAIL on balance. Two further samples were
**balanced (0 unclosed) → PASS**, at 88.9 and 87.5 tok/s decode.

Because sampling is stochastic, n=1 cannot establish a regression. Grading the previous
build's T1 output with the identical parser gives `balanced=True, 0 unclosed`, so the prior
build also passes — but it is also a single sample. The honest statement is: **T1 emits
unbalanced markup intermittently (1 of 3 here), on both builds.** Re-run before treating a
single T1 failure as a regression.

## Patch applicability

`gguf_k_dims.py` was not re-run for this image, but the model is unchanged from the
2026-09-23 analysis: all quantized weight tensors have K ∈ {5120, 6144, 17408}, every one a
multiple of the 128 dense stride, and the single violating tensor (`ssm_conv1d.weight`,
K=4) is **F32**, which is not registered for the cm1 int8 path. **This model does not trigger
the A-operand out-of-bounds read**, so the missing patch is not a correctness risk here. It
is a latent risk for a future model, which is why `main` was fixed.

## Verdict

**No regression attributable to b11368, and no reason to promote it over what is already
running.**

- T1/T2 pass with strong numbers (94.6 / 99.2 tok/s decode, 74.7 % / 79.8 % draft acceptance).
- A1 and A3 pass with verified, non-fabricated results; A3's 258.6 cm matches the figure
  seen on SYCL and on both Vulkan configs.
- The two failures (A2 GPU naming, V2/V3) are either a model-level behaviour already in the
  ledger (V2/V3) or a single non-gating field (A2).
- This is consistent with the triage: the 4 Vulkan commits between b11284 and b11368 are all
  vendor-gated away from this card, are CPU-path, or are pure diagnostics.

**Production remains on `b11165`** (fingerprint `b1-8212c78`), which is what was already
promoted. **Do not promote b11368**: it carries no upstream change worth having, and it is
the one build that is missing our local patch. The patch arrives with the next build.

**What would change this:** a consistent T1 imbalance across several samples; a V3 reading
that is *not* `113S` and *not* `118S`; or any crash/OOM signature. None appeared.

**Honest boundaries of this run**

1. **XTX only.** No B70 data — the GDN tuning commit (`5c200e0c8`), which is the one change
   in this window with a real B70-side effect (`lanes_per_column` 8 → 16 on Intel), is
   untested here.
2. **Trim auto-tune did not fire**, so agent tasks compacted at dsh's stock ~37 % trigger
   rather than the intended ~80 %. Consistent with prior runs, but not the intended shape.
3. **Vision prefill tok/s is not reportable** (image tokens excluded from `prompt_n` under
   `--no-mmproj-offload`); only TTFT and decode are meaningful for V1-V3.
4. **V1-V3 decode windows are short** (4-35 s). Small differences there are not meaningful.
5. Single sample per task (except T1, run 3×). Stochastic backend; individual failures need
   a re-run before being called regressions.
