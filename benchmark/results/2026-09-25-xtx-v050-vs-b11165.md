## 哪些差异可信，哪些是噪声

**可信（decode 窗口够长，36–94 秒）**

- **t1_html +19.7%**：36s → 42s 的生成窗口，是本次最实在的一项提升，且 TTFT 从 1.12s 腰斩到 0.53s、prefill 38.4 → 164.4 t/s、draft 接受率 65.4% → 85.8%。四项同向、幅度都大，不像抖动。
- **t2_svg +0.8%**：94s / 80s 窗口，基本持平。
- **t3/t4/t5 −4.6% / +1.5% / −5.1%**：agent 任务、28–89s 窗口，都在正常跑批波动内，**不构成回归**。

**不可信（decode 窗口不足 3 秒）**

- **V3 −33.2%** 看着最吓人，实际是 53 → 72 个 token、**0.62s → 1.25s** 的窗口。首 token 排队抖动就能造成几十个百分点。
- **V2 −7.5%** 是更明确的证据：同一个 prompt，两次跑出的**输出长度差了一倍**（116 → 247 token）。输出长度不同 → decode 状态混合不同 → 速率自然不同，跟后端无关。

**所以：唯一可下结论的是 t1_html 明显变快、t2 持平，其余都在噪声里。** 我没有把 V3 的 −33% 当作回归上报。

## 行为层面：两个昨天的结论被原样复现

这两项与后端版本无关，但两边数据可直接对照，值得记一笔：

**1. XTX t5 的算术错误一模一样。** 昨天 #6 记录它把 3 月算了两次（报 217，实为 258）。本次 b11165 **输出几乎逐字相同**——同样是 217.0 cm、"严格截止 12 月 31 日"、同样以 extsol.ca 的 258 cm 作为对照说明。**跨版本、跨天稳定复现，是模型行为而非后端问题。**

**2. V3 速度级别仍然是 `T118S`。** 昨天记录"全图→`S`、右半裁切→`T`"的呈现不稳定，本次全图直出 **`T118S`**。尺寸 `255/70R18` 稳定正确，速度级别依旧不可靠——**确认这是一致性的老问题，不是本次引入的。**

（V1 五项子答案、V2 接口清单两次也一致：千律/LV6/850%/Lv.5防8s/400%/-1000/75%+沉默，DIMM1-4 / PCIE16X / M2_1-M2_2 / 完整 I/O 集合。）

## 结论

| | |
|---|---|
| **净效应** | 混合偏正：t1_html **+19.7%**、t2 持平，agent/vision 差异在噪声内 |
| **回归证据** | **无**。没有任何一项在足够长的测量窗口里出现可信的下降 |
